# RoboPhone Avatar ER Core

This module now implements the ER orchestration layer only. Specialist capabilities live outside ER and are called through provider interfaces.

## Architecture

The design follows:

`Detect -> Interpret -> Decide -> Call specialist module if needed -> Respond -> Update state -> Repeat`

Modules:

- `models.py`: ER-facing contracts and state models.
- `state.py`: Persistent in-memory avatar session state store with bounded history.
- `commands.py`: Deterministic control-command interpreter. Critical mute and responsiveness commands do not depend on an LLM.
- `intent.py`: Heuristic intent classifier with a clean swap point for a future ML or LLM classifier.
- `decision.py`: Central ER orchestration layer.
- `providers.py`: Provider contracts for emotion, speech, manual-Q&A, and motion modules.
- `adapters.py`: Thin adapters that call external modules such as `robophone/stt`, `robophone/ground_eval`, and Gemini for emotion-aware teacher responses.
- `adapters.py`: Thin adapters that call external modules such as `robophone/stt`, `robophone/ground_eval`, and Gemini for emotion-aware teacher responses and conversation routing.
- `coordinator.py`: Live polling coordinator for camera and mic driven demos.
- `response.py`: Response formatting for tone and responsiveness modes.
- `api.py`: Public integration entry point.
- `demo.py`: Pure ER simulation script.
- `demo_live_emotion_er.py`: live Camo emotion input into ER.
- `demo_live_chat.py`: chat-only ER loop for typed child replies without camera input.
- `demo_live_emotion_stt.py`: live Camo emotion plus STT into ER.
- `demo_live_full.py`: live Camo emotion plus STT plus grounded Q&A.

## Data Flow

1. External code sends a perception payload to `process_avatar_input(perception_payload)`.
2. Payload is normalized into `PerceptionInput`.
3. Speech text is checked by the rule-based command interpreter and intent classifier.
4. The decision engine decides whether to stay quiet, confirm a settings change, call a manual-Q&A provider, or offer proactive help.
5. Specialist modules stay outside ER:
   - `robophone/emotion_rt` detects emotions.
   - `robophone/stt` transcribes speech.
   - `robophone/ground_eval` answers RoboPhone manual questions at runtime.
6. Emotion-aware teacher replies can be generated by Gemini using recent emotion history and recent speech snippets from ER state.
7. Child replies can be routed by Gemini into either general teacher conversation or RoboPhone manual help via `ground_eval`.
8. Response formatting adjusts verbosity and tone.
9. Updated avatar state is persisted in memory and returned to the caller.

## Public API

```python
from avatar_er import process_avatar_input

result = process_avatar_input(
    {
        "emotion_signal": {
            "emotion": "confused",
            "confidence": 0.82,
            "source": "robophone.emotion_rt",
            "source_face_id": "student_1",
            "is_stable": True,
        },
        "speech_signal": {
            "text": "I don't understand how to graph sin",
            "source": "robophone.stt",
        },
        "current_task": "building RoboPhone Blockly graph",
    }
)
```

Returned shape:

```python
{
    "should_speak": True,
    "response_text": "No problem. Start with ...",
    "updated_state": {...},
    "action_type": "manual_guidance",
    "reason": "...",
    "payload": {...},
}
```

## Demo

Run:

```bash
python3 -m avatar_er.demo
```

The demo simulates:

- no voice with a confused face
- `"stop responding"`
- `"talk less"`
- `"I don't understand how to graph sin"`
- `"how do I display text on the LCD?"`
- neutral face with no speech

The pure demo uses a local mock manual-Q&A provider so it never requires a real LLM call.

## Live Demos

Set your Gemini key once in `robophone/.env`:

```bash
GEMINI_API_KEY=your_api_key_here
```

`avatar_er` now reads `robophone/.env` automatically for Gemini. Shell export is optional and only used as a fallback.

Emotion-only into ER with live teacher responses:

```bash
./.venv/bin/python -m avatar_er.demo_live_emotion_er \
  --camera-index 0 \
  --backend-type hf_vit \
  --model-id mo-thecreator/vit-Facial-Expression-Recognition
```

Emotion plus STT:

```bash
./.venv/bin/python -m avatar_er.demo_live_emotion_stt \
  --camera-index 0 \
  --backend-type hf_vit \
  --model-id mo-thecreator/vit-Facial-Expression-Recognition \
  --stt-api-url http://localhost:8001/transcribe
```

Full loop with grounded Q&A:

```bash
./.venv/bin/python -m avatar_er.demo_live_full \
  --camera-index 0 \
  --backend-type hf_vit \
  --model-id mo-thecreator/vit-Facial-Expression-Recognition \
  --stt-api-url http://localhost:8001/transcribe
```

The live emotion ER loop now:

- prints only when the stable emitted emotion changes
- suppresses repeated `None`/empty detections
- uses Gemini to produce short teacher-style responses instead of hardcoded emotion text
- includes recent emotion history and recent speech snippets in the Gemini prompt

Live emotion plus typed conversation:

```bash
./.venv/bin/python -m avatar_er.demo_live_conversation \
  --camera-index 0 \
  --backend-type hf_vit \
  --model-id mo-thecreator/vit-Facial-Expression-Recognition \
  --interactive-replies
```

You can also seed the first child reply from a CLI argument:

```bash
./.venv/bin/python -m avatar_er.demo_live_conversation \
  --camera-index 0 \
  --backend-type hf_vit \
  --model-id mo-thecreator/vit-Facial-Expression-Recognition \
  --initial-child-message "I don't get how to graph sin"
```

The conversation path now:

- stores bounded in-memory conversation history in ER session state
- saves teacher and child turns with route/source metadata
- uses Gemini to classify a child reply as `general_conversation` or `manual_help`
- sends `manual_help` turns to `ground_eval`
- keeps `general_conversation` turns in Gemini

Two-terminal shared-session workflow:

Terminal 1, emotion only:

```bash
./.venv/bin/python -m avatar_er.demo_live_emotion_er \
  --camera-index 0 \
  --backend-type hf_vit \
  --model-id mo-thecreator/vit-Facial-Expression-Recognition \
  --session-path avatar_er/state/live_session.json
```

Terminal 2, chat only:

```bash
./.venv/bin/python -m avatar_er.demo_live_chat \
  --interactive-replies \
  --session-path avatar_er/state/live_session.json
```

Or seed the first typed child turn:

```bash
./.venv/bin/python -m avatar_er.demo_live_chat \
  --initial-child-message "I don't get how to graph sin" \
  --session-path avatar_er/state/live_session.json
```

These are still separate processes, but they now share one local JSON-backed ER session file. The emotion terminal publishes stable emotion state into that session, and the chat terminal reads the same session before answering.

## Runtime Manual-Q&A Integration

`GroundEvalManualQaProvider` calls the new `robophone.ground_eval.runtime` service layer.

ER stays responsible for:

- whether to respond
- how much to say
- tone and cooldown enforcement

`ground_eval` stays responsible for:

- grounding the question against the RoboPhone manual
- returning answer content

## What Is Stubbed or Mocked

- Unit tests use mock manual-Q&A and mock Gemini emotion-response backends plus fake clocks.
- Unit tests also use mock Gemini route and conversation providers.
- If Gemini is unavailable or `GEMINI_API_KEY` is missing from `robophone/.env` and the shell, ER falls back to local teacher-style responses.
